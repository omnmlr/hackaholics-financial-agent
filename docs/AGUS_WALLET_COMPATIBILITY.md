## What account and wallet selection mean

- Stock React Native `transact` starts one short native association and closes it on return. The 3.0.2 Android bridge uses one session mutex and starts an implicit `ACTION_VIEW` intent. With Phantom and Solflare installed, a generic intent leaves wallet selection to Android's resolver, including saved defaults or a chooser. An optional wallet-supplied HTTPS `wallet_uri_base` is designed for subsequent associations and cannot identify the app before the first connection. [MWA Android bridge source](https://github.com/solana-mobile/mobile-wallet-adapter/blob/main/js/packages/mobile-wallet-adapter-protocol/android/src/main/java/com/solanamobile/mobilewalletadapter/reactnative/SolanaMobileWalletAdapterModule.kt) · [MWA specification](https://solana-mobile.github.io/mobile-wallet-adapter/spec/spec.html)
- AGUS selects the named package on each association, bypassing the generic Android resolver. The version-checked Expo config plugin changes the native intent with `setPackage` and removes request parameters from wallet API logs. It keeps the official Android SDK's association, encryption and RPC. The private routing URI uses a scheme the stock SDK rejects, so an old binary fails before a generic wallet association. This spike uses the package-scoped `solana-wallet:` handler. Vendors that require their returned HTTPS endpoint for reacquisition need a package-scoped HTTPS route validated on-device. Package name is an Android routing identifier. A production trust policy should also account for APK signing identities and certificate rotation. [Android intent package behavior](<https://developer.android.com/reference/android/content/Intent#setPackage(java.lang.String)>) · [MWA integration guide](https://github.com/solana-mobile/mobile-wallet-adapter/blob/main/android/docs/integration_guide.md)
- MWA authorizations are opaque bearer tokens scoped to the issuer and the accounts it returned. When possible, `authorize` with an existing token can renew silently. MWA 2.0 treats requested `addresses` as a hint. The installed 3.0.2 bridge sends legacy `reauthorize` with token and identity only on legacy peers. AGUS checks the returned accounts for the exact sender and Devnet capability before allowing signing. Uninstall, revocation, account/network changes and token policy can require another link. A wallet may rotate a grant and invalidate another account's saved copy. Only the active account's returned grant is renewed by this spike. [Authorization and errors](https://solana-mobile.github.io/mobile-wallet-adapter/spec/spec.html)
- The wallet renders its own UI. An approval sheet can feel like a popup while still being another app's Android activity. Some wallets may display a fuller app switch or require a biometric/PIN unlock or account selection. AGUS can launch the target from its own button. The user may still need to unlock the wallet, switch the active account or relink. The actual presentation and number of prompts for each build need to be recorded. [Solana Mobile integration guide](https://github.com/solana-mobile/mobile-wallet-adapter/blob/main/android/docs/integration_guide.md)
- The spike calls MWA `sign_and_send_transactions` for a single reviewed Devnet transaction. AGUS supplies a minimum context slot and verifies exact message bytes and the execution result against Devnet. A vendor that leaves this method unavailable or rewrites message bytes needs its own compatibility decision and potentially a sign-only adapter. The older AGUS server-mediated sign-only path remains available separately. Origin attestation via Digital Asset Links can block association for the current signing certificate and identity. An MWA token and a vendor deep-link session use different formats and transports. [MWA transaction and attestation methods](https://solana-mobile.github.io/mobile-wallet-adapter/spec/spec.html)

## Vendor alternatives and source reuse

- Phantom, Solflare and Backpack publish encrypted deep-link flows. A first connect opens the vendor app and obtains a public key plus a session. Later method calls reuse that vendor's session and the application's encryption context, open its universal link and redirect to AGUS. Phantom and Solflare document that deep-link sessions have no fixed expiry while remaining subject to disconnect and invalidation after an account or chain change. Backpack describes comparable validation. An iOS or non-MWA fallback would need authenticated response correlation and vendor/account/chain-scoped storage. Vendor SDK docs are evidence for their own transport. [Phantom](https://docs.phantom.com/phantom-deeplinks/handling-sessions) · [Solflare](https://docs.solflare.com/solflare/technical/deeplinks/handling-sessions) · [Backpack](https://docs.backpack.app/deeplinks/handling-sessions)
- The Solana Mobile MWA SDK is Apache-2.0, and the existing app already pins the web3.js bridge to 3.0.2. Solana Kit is suitable for future RPC and instruction construction, with `@solana-mobile/mobile-wallet-adapter-protocol-kit` and Wallet UI's React Native Kit adapter available. Wallet UI's documented app-level provider takes one chain and one authorization cache, and its authorization hook returns one current account. These examples are useful for setup and signing. AGUS still needs app/account-scoped storage and provable wallet routing. This spike reuses the existing web3.js setup and repository-tested classic SPL codecs. [MWA license](https://github.com/solana-mobile/mobile-wallet-adapter/blob/main/LICENSE) · [Expo Kit Wallet template](https://solana.com/developers/templates/expo-kit-wallet) · [Wallet UI providers](https://wallet-ui.dev/react-native/providers/) · [Wallet UI source and license](https://github.com/wallet-ui/wallet-ui)
- Solflare's published SDK targets extension, web and mobile connectivity from a dapp. Its source is useful for evaluating session UX and transport selection. Confirm the published license and native compatibility before incorporating code. The spike uses the documented MWA APIs and contains no copied vendor transport code. [Solflare SDK](https://docs.solflare.com/solflare/technical/integrate-solflare/solflare-wallet-sdk) · [Source](https://github.com/solflare-wallet/solflare-sdk)
- Public Solana RPC suffices for SOL plus parsed classic SPL and Token-2022 balances. Helius DAS `getAssetsByOwner` can add pagination, fungible tokens, metadata and native balance for production indexing. Quote coverage and freshness still require explicit checks. Keep a provider key server-side. CoinGecko supplies timestamped market prices for SOL, USDC and USDT in the spike. [Solana RPC](https://solana.com/docs/rpc/http/gettokenaccountsbyowner) · [Helius DAS](https://www.helius.dev/docs/api-reference/das/getassetsbyowner) · [CoinGecko Simple Price](https://docs.coingecko.com/reference/simple-price)

## Download and install the phone-test build

Download the [ARM64 Devnet test APK](https://github.com/omnmlr/hackaholics-financial-agent/releases/download/agus-wallet-control-phone-test-20261122/AGUS-Wallet-Control-Devnet-arm64.apk).
The [SHA-256 file](https://github.com/omnmlr/hackaholics-financial-agent/releases/download/agus-wallet-control-phone-test-20261122/SHA256SUMS.txt)
lists `c09bac72fbec54840e098cd01c55dc7de3d15d6a8c722d37fcccae7101c3ac03`.
On Android, open the APK from Downloads and allow the browser or Files app to
install it if prompted. If the earlier Expo-debug AGUS build is installed under
`app.agus.prototype`, Android will refuse an in-place update because the signing
certificate changed. Removing the earlier app also removes its local test data.

This build sends a dedicated staging HTTPS origin in the **Solana wallet control**
panel's native MWA authorization requests. The origin's public statement lists
`app.agus.prototype` and exactly the APK's test certificate. It serves anonymous
HTTPS 200 with a JSON content type and zero redirects. Google's Digital Asset
Links API returned `linked: true`. A rebuild signed by another certificate needs
a matching statement. The app's existing backend configuration is separate from
this MWA identity. [Public Digital Asset Links statement](https://agus-wallet-devnet-identity-2o66ayctk-youngfrankcreator-7012.vercel.app/.well-known/assetlinks.json)

**Remaining wallet-specific limitation.** The certificate and public statement are
verified independently. Phantom and Solflare still need to accept the origin and
Devnet on a physical phone. Native MWA may report `-1` for a declined authorization
or failed origin verification. The spec describes `-100` as an Android browser
challenge. If a wallet returns it to this native build, record the wallet version and
exact prompt. This build uses native Digital Asset Links verification.
[MWA Android identity verification](https://solana-mobile.github.io/mobile-wallet-adapter/spec/spec.html#android)

## Physical-device acceptance

Use the APK built from this branch or build from a clean checkout. Confirm both wallets are current official builds and record AGUS commit, APK SHA-256, Android version, model, app version and relevant Devnet settings. Use a physical Android ARM64 device and two distinct disposable wallet accounts. Do not import either recovery phrase into AGUS. Use test SOL only. CoinGecko valuation acceptance uses a public mainnet address in watch-only mode.

1. Install Phantom and Solflare on the same Android phone. Create or select one Devnet account per app. Enable Devnet/testnet mode in each wallet as applicable. Fund the disposable accounts with the official [Solana faucet](https://faucet.solana.com/) or an existing disposable Devnet wallet. Use a recipient that already has a small Devnet SOL balance.
2. Install AGUS and open **Solana wallet control**. The panel uses device-local storage and public RPC. A banking login is unnecessary for this panel.
3. Tap **Link Phantom**. Note whether a resolver, vendor sheet or full vendor activity appears, and record every account selection, unlock, consent and return step. Repeat for **Link Solflare** with Phantom still installed. Each named button should resolve to its named app. A missing app or missing MWA handler should be reported without trying the other app.
4. Add Phantom's public address as Devnet watch-only. It should appear once with Phantom's signing route. Force-stop and reopen AGUS. Both addresses and app labels should reappear. Tap **Refresh balances and prices** and compare both wallet balances.
5. Select **Pay from Phantom**. Leave the token mint blank, supply the funded recipient, and review `0.001` SOL plus fee. Tap **Authorize and send with wallet**. Record any renewed consent and the actual signing UI. Approve exactly once. Wait for **Finalized on Devnet** or tap **Check on-chain status**. Record the public AGUS reference and signature. Confirm `meta.err` is null and compare the exact sender, recipient and 1,000,000 lamports in [Solana Explorer on Devnet](https://explorer.solana.com/?cluster=devnet).
6. Repeat from Solflare without disconnecting Phantom. Reopen AGUS and make another Phantom payment with a different amount. Record all three independent receipts and whether token renewals restored the originally authorized address without a manual reconnection.
7. Reject an approval, try a different active wallet account, test insufficient SOL and wait for a review to expire before authorizing. AGUS should show the rejection or validation outcome, require a new review for an expired blockhash, and issue no signing request when the selected address is missing. While a result is pending, try an identical review and verify that AGUS blocks submission. Review the saved reference before retrying after a process kill or connection loss.
8. For an SPL test, seed the sender's associated token account with a known classic mint on Devnet. Circle's Devnet test-USDC mint is `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`. A self-created mint is a separate test asset. Provide its mint address, verify amount and possible recipient ATA rent, and repeat the approval. Record the finalized signature and exact mint, source ATA and recipient ATA changes. [Circle mint registry](https://developers.circle.com/stablecoins/usdc-contract-addresses)
9. Run the same connection, payment and restart cases for Backpack as an extra matrix row. For Seeker, run a separate Seeker Connect integration on supported hardware before adding it to the launch matrix. Report failures with vendor, app version, distribution, chain, stage and exact error. Record screenshots and public signatures where available. Keep tokens and other credentials out of the evidence.
