## 2. Comprehensive Diagnosis Matrix

| Classification | Issue Description | Exact Source Line Citation | Mechanism & Reproduction | Impact & Remediation |
|---|---|---|---|---|
| **Confirmed Bug** | **Invalid MWA Reauthorization Call in `select()`** | `apps/mobile/src/crypto-signer.ts:86-91` | `wallet.authorize` is invoked passing `auth_token: token`. Standard MWA protocol requires calling `wallet.reauthorize({ auth_token, identity })`. Protocol-compliant wallets either reject `authorize` with unknown property errors or present a full authorization modal on every transaction. | Masked in CI by permissive test mock in `crypto-mobile.test.ts:133-140`. Remediated by calling `wallet.reauthorize` with fallback to `wallet.authorize` on `ERROR_REAUTHORIZE`. |
| **Confirmed Bug** | **`signAndSendTransactions` Return Type & Base58 Parsing** | `apps/mobile/src/crypto-signer.ts:297-306` | In MWA wire specification, `signAndSendTransactions` returns `Uint8Array[]` (raw 64-byte Ed25519 signatures). `crypto-signer.ts:302` passes this directly to `@scure/base` `base58.decode(signature)`, which throws `Error: join.decode: string expected`. | Discards successfully broadcast on-chain transactions as `WALLET_SIGNATURE_UNAVAILABLE`. Also drops signatures in `parseSavedAttempt` (`crypto-device-state.ts:20`). Remediated by polymorphic signature normalization (`Uint8Array` -> base58 string). |
| **Confirmed Bug** | **Premature Launch Marker Bricks Retries** | `apps/mobile/src/crypto-signer.ts:277-280` | Double-spend idempotency marker `agus.crypto.launch.${userId}.${attempt.id}` is persisted to `SecureStore` *before* `transact()` is invoked. If an abort occurs during `association` or `authorization` (e.g. user cancels wallet prompt, connection timeout), the attempt was never broadcast to Solana. | Any subsequent retry of `handoff()` immediately returns `{ kind: "unknown" }` via line 278, permanently bricking the payment attempt. Remediated by committing marker only at `stage === "submission"`. |
| **Confirmed Bug** | **AppState Background Session Lock Race** | `apps/mobile/CryptoDeviceHarness.tsx:367`; `apps/mobile/src/session.ts:69-70` | When switching from AGUS to external wallet (Phantom/Solflare), Android transitions AGUS to background, triggering `AppState.addEventListener("change")` in `CryptoDeviceHarness.tsx:214` to call `lockSession()` (`unlocked = false`). When the wallet returns and `pay()` calls `recover()`, `session.ts:70` throws `Error: LOCAL_SESSION_LOCKED`. | Crashes the return payment flow with an unhandled exception until user manually unlocks session. Remediated by graceful session lock deferral or catching `LOCAL_SESSION_LOCKED` during handoff recovery. |
| **Plausible Cause** | **Phantom Biometric Stall and Force-Close on Nov 22 Handset** | PR #46 / Nov 22 Journal; `apps/mobile/plugins/with-wallet-package.cjs:37-39` | Stock MWA SDK 3.0.2 enforced `ASSOCIATION_TIMEOUT_MS = 10000` (10s). When Phantom prompted for biometric unlock, the prompt exceeded 10s, tearing down the association WebSocket mid-handshake and crashing Phantom. | Addressed in AGUS Expo config plugin by increasing timeout from 10,000 ms to 45,000 ms (`with-wallet-package.cjs:38`). |
| **Plausible Cause** | **Digital Asset Links 404 & Phantom "Unverified Identity" Warning** | `docs/agus-crypto/ANDROID_DEVICE_TEST.md:22`; `apps/mobile/app.json:44-46` | Phantom queries `https://<identity.uri>/.well-known/assetlinks.json` to verify package `app.agus.prototype` certificate fingerprint. On Nov 22, the Vercel identity host returned HTTP 404, prompting Phantom's red security banner. | Remediated by publishing verified SHA-256 certificate fingerprint in `/.well-known/assetlinks.json` on the Vercel identity host. |
| **Plausible Cause** | **Solflare "Low Power Mode" Blocker** | Nov 23 Journal; `apps/mobile/src/crypto-wallet-policy.ts:27-28` | Android Battery Saver / Low Power Mode restricts background loopback sockets (`127.0.0.1:<port>`). Solflare detects battery state and aborts MWA: *"Your device is in low power mode. Deactivate it to enable connection and signing."* | Correctly classified as `WALLET_POWER_RESTRICTION`. Runbook `ANDROID_DEVICE_TEST.md:29` requires disabling Battery Saver for device acceptance. |
| **Device Uncertainty** | **Hardware-Backed Keystore across OS Suspension** | Android KeyStore / `WHEN_UNLOCKED_THIS_DEVICE_ONLY` | Android hardware-backed keystore key accessibility and cryptographic handle invalidation under aggressive OEM background task killers (MIUI, OneUI) cannot be verified in desktop simulators. | Documented as device-only uncertainty requiring physical handset verification with clean install. |
| **Device Uncertainty** | **BiometricPrompt vs MWA Association Handshake Concurrency** | Android OS BiometricPrompt Lifecycle | Concurrency between Android OS biometric dialogs and local WebSocket loopback ports (`127.0.0.1:<port>`) requires live handset verification. | Documented as device-only uncertainty requiring physical handset verification. |
| **Device Uncertainty** | **OEM Deep Link Resolution & App Links Verification** | `apps/mobile/app.json:21-50` (`autoVerify: true`) | Android OEM-specific App Links autoVerify behavior across Samsung, Pixel, and Xiaomi devices cannot be verified without physical devices. | Documented as device-only uncertainty requiring physical handset verification. |
