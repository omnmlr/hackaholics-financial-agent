### 2.2 Retracted Hypotheses (Verified Compliant Against MWA SDK v3.0.2)

Independent inspection of the installed `@solana-mobile/*` packages in `node_modules` refuted two earlier claims from the initial draft:

1. **Retracted: "`wallet.authorize` with `auth_token` violates MWA"** (`apps/mobile/src/crypto-signer.ts:86-91`)
   - **Verified SDK Behavior**: In `@solana-mobile/mobile-wallet-adapter-protocol@3.0.2` (`lib/types/index.d.ts:159-166`, `lib/esm/index.native.js:158-201`), `AuthorizeAPI.authorize` explicitly accepts `auth_token?: AuthToken`. `handleMobileWalletRequest` intentionally falls through from `case "authorize":` to `case "reauthorize":`: on `protocolVersion === "legacy"`, it rewrites RPC `method` to `"reauthorize"` with `{ auth_token, identity }`; on `protocolVersion === "v1"`, it sends RPC `method = "authorize"` preserving `chain`, `addresses`, `auth_token`, and `identity`.
   - **Why Replacement with `wallet.reauthorize` Was Withdrawn**: Calling `wallet.reauthorize({ auth_token, identity })` on MWA `v1` causes `handleMobileWalletRequest` (`index.native.js:188-200`) to rewrite RPC `method` to `"authorize"` *without* `chain` or `addresses: [wanted]`, which would introduce a regression. Also, MWA protocol error code for auth failure is numeric `-1` (`ERROR_AUTHORIZATION_FAILED`, `index.d.ts:47`), not string `"ERROR_REAUTHORIZE"`.
2. **Retracted: "`signAndSendTransactions` returns `Uint8Array[]` causing `base58.decode` crash at line 302"** (`apps/mobile/src/crypto-signer.ts:297-306`)
   - **Verified SDK Behavior**: `crypto-signer.ts:12` imports `transact` from `@solana-mobile/mobile-wallet-adapter-protocol-web3js@3.0.2`. In `lib/types/index.d.ts:3-12` and `lib/esm/index.native.js:27-43` (line 42), `signAndSendTransactions` returns `Promise<TransactionSignature[]>` (`string[]`) via `base64EncodedSignatures.map(base64ToUint8Array).map(base58FromUint8Array)`. Thus `crypto-signer.ts:302` (`base58.decode(signature)`) receives base58 strings as intended. (Only `signMessages` returns `Uint8Array[]` at `index.native.js:45-53`, which `crypto-signer.ts:178-192` already handles as bytes.)
