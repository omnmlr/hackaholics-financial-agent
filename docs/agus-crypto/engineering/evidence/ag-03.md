## 4. Prioritized Vulnerability and Remediation Findings

### Finding 1 (Critical): Excessive Database Role Privileges on Immutable Financial Ledger Tables
- **File / Lines**:
  - `scripts/sql/runtime-role.sql:6` (grants broad privileges to `agus_runtime`)
  - `tests/helpers/shared-platform.ts:14,30` (applies the same broad grant pattern to ephemeral `agus_market_role_<uuid>`)
- **Vulnerability**:
  The application runtime role (`agus_runtime`) receives `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public`. While legacy tables (`agus_p2p_events`, `agus_legacy_authority`) had `UPDATE` and `DELETE` revoked, **no revocation** was applied to:
  - `agus_crypto_chain_events` (audit ledger of on-chain activity)
  - `agus_crypto_wallet_events` (tenant-to-chain-event attribution ledger)
  - `agus_crypto_receipts` (finalized settlement records)
  - `agus_crypto_reviews` (financial intent proposals)
  - `agus_audit` (system audit log)
- **Impact**:
  A compromised application process or future SQL injection vulnerability could rewrite financial history, alter wallet event attribution, delete receipts, or clear audit records.
- **Remediation**:
  Authored `scripts/sql/runtime-role-least-privilege.sql` (verified in `NEG-11` against PGlite) to explicitly execute:
  ```sql
  REVOKE UPDATE, DELETE ON 
    agus_crypto_chain_events,
    agus_crypto_wallet_events,
    agus_crypto_receipts,
    agus_crypto_reviews,
    agus_audit
  FROM agus_runtime;
  ```

### Finding 2 (High): Absence of PostgreSQL Row Level Security (RLS)
- **File / Lines**:
  - `migrations/0001_initial.sql` through `migrations/0027_crypto_requests.sql`
- **Vulnerability**:
  PostgreSQL Row-Level Security (RLS) is not enabled on any table in the schema. Multi-tenant isolation relies entirely on developers consistently including `WHERE owner = $1` in every TypeScript query.
- **Impact**:
  A single missing `WHERE owner = $1` clause in a query or administrative script instantly causes cross-tenant data leakage.
- **Remediation Proposal**:
  Enable RLS on all 18 tenant-owned `agus_crypto_*` tables and define policies matching `owner` as `text` (since `agus_users.id` and `owner` are `text` per `migrations/0004_identity_platform.sql:2` and `0022`–`0027`) using transaction-scoped session configuration:
  `USING (owner = NULLIF(current_setting('app.current_user_id', true), ''))`.
  Documented in detail in `scripts/sql/runtime-role-least-privilege.sql` and verified in `NEG-11`.

### Finding 3 (Medium): Unauthenticated Reference Endpoint Rate-Limiting Gap
- **File / Lines**:
  - `src/app/api/v1/crypto/[[...path]]/route.ts:73-74`
  - `src/server/crypto/requests.ts:205-228`
- **Vulnerability**:
  `GET /api/v1/crypto/share/:reference` is unauthenticated and queries the database for payment details.
- **Impact**:
  An external distributed botnet could flood this endpoint to exhaust database connection pool resources.
- **Remediation Proposal**:
  Implement Caddy/Cloudflare edge rate-limiting rules (e.g. max 60 requests/minute per IP) in deployment tooling (AG-01).
