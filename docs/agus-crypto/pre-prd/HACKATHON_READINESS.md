## Demo journeys and 80-point acceptance evidence

Run the core journey with Pocket and invoicing disabled. Use disposable test funds, an explicitly labeled cluster and supported mints. Separately label any fixtures, local simulations or recorded device results.

1. **Understand.** Link Phantom and Solflare on the actual signed APK. Show distinct wallet balances and a combined view. Demonstrate duplicate-route deduplication and watch-only visibility. Trace a finalized internal transfer from wallet A to wallet B, explain the per-wallet change, show the fee separately and keep that transfer out of external income/spending. Ask about the transfer and about received USDC over a defined range. The answer cites the actual event and makes any missing history visible.
2. **Act.** Start an ordinary SOL or supported classic SPL transfer in chat. Show why the proposed wallet is eligible, let the user confirm its source, and review exact details before the intended wallet opens. Return to a verified on-chain receipt with its signature, reviewed bytes, source, mint or SOL, amount and finality. For the two-wallet signing claim complete Phantom → Solflare → Phantom on the same device, with no silent fallback and three distinct finalized references. One route is the feasible initial integration goal. Missing the second route reduces the demonstrated score.
3. **Monitor.** Enable one useful rule for an owned wallet and show a real finalized event creating one in-app alert without a fresh chat prompt. Reprocess the event to verify deduplication and open the event evidence from the alert. Push delivery can wait. A watch-only route cannot produce a signing action.
4. **Recover.** Include a decline and a pending/lost-return case. Reopen the app, reconcile the known attempt before offering any new submission, and verify no false receipt or duplicate debit. Record versions, approval and unlock counts, cold/warm return, actual failures and final transaction links. Capture a continuous handset demo and attach a reproducible signed build.

The stretch extension is a single verified source-wallet swap **or** optional Pocket activation, funding, in-app spending, policy rejection, revoke and root exit. A swap needs compatible test liquidity, decoded and allowlisted instructions, a fresh quote, minimum output and verified result. An external review of a quote alone earns no live execution credit. Pocket needs a validated on-device signing and recovery route. If the condition fails, keep that capability off live by November 26. A labeled simulation can explain the intended design, with the demonstrated score graded separately.

The realistic slice is Solana-only with SOL plus one supported classic SPL mint, two wallet views, a bounded activity window, a small set of grounded questions, one in-app alert rule, and one independently verified signer path if the device blocker is cleared. A second signing route is the acceptance target for 80, and should be labeled unverified if it misses. If neither signer clears the gate, demonstrate the real portfolio and monitoring sequence and explicitly label execution as a local or recorded proof. The strongest roadmap and B/C scores are conditional, not promises.

Defer broad position coverage, historical PnL and long backfill, multiple swap routes, push/digest depth, Backpack release approval, richer budgets, recurring execution, and full Pocket recovery until each is validated. These remain product capabilities. Supporting tools can be demonstrated if already ready, without replacing the main journey.

## Parallel ownership and founder acceptance

Frontend uses the versioned fixtures to build portfolio, chat evidence, alert and payment states. Backend implements matching portfolio/history, grounded answer, alerts and exact-draft verification contracts. The Android native lane validates identity, wallet capability, return and authorization. Leads can swap staffing, but must share the same stable types and vectors. Frontend/backend integration begins at the Nov 25 checkpoint. On the founder's physical device, record Android and wallet versions, package/signing identity, both distinct accounts after restart, actual consent and unlock counts, and battery saver behavior for Solflare. Investigate the Phantom warning/force-close without bypassing vendor checks. Test cold/warm starts, cancellation, wallet switch and process loss before any replacement attempt. Confirm public Devnet signatures from the exact reviewed operations. If shipping Pocket, also confirm in-app user presence, rejection/cancellation, revoke and root recovery/exit after app-state loss.
