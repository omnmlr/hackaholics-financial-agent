# Competitor architectures and AGUS evidence

## Agentic (Solana Agent Wallet Adapter)

**Implemented in source.** Agentic exposes Solana tools over MCP and a shared action service. Signing is routed to a pluggable wallet backend. Its web adapter discovers Wallet Standard wallets. The Android controller selects an installed wallet, caches wallet authorizations, checks the selected account and routes signing through MWA. Its iOS bridge documents encrypted vendor links for Phantom, Solflare and Backpack and a separate WalletConnect path for Jupiter. A real signing request produces an approval resource that the client can surface as a URL or poll. The same interface also has a mock backend. [MCP tools and bridge](https://github.com/mstevens843/solana-agent-wallet-adapter/blob/f00f17f8283c1fca259cefc5d402ef07b463b899/packages/mcp-server/README.md) · [Web adapter](https://github.com/mstevens843/solana-agent-wallet-adapter/blob/f00f17f8283c1fca259cefc5d402ef07b463b899/packages/wallet-standard-web/README.md) · [Android MWA controller](https://github.com/mstevens843/solana-agent-wallet-adapter/blob/f00f17f8283c1fca259cefc5d402ef07b463b899/apps/android-twa/app/src/main/java/com/agentic/wallet/mwa/MwaController.kt)

**Publication and test evidence.** GitHub Release `v1.0.5` includes an Android APK and AAB. Agentic's MCP documentation reports a confirmed mainnet transfer in real-wallet bridge mode. That report establishes the project's own claim for the bridge flow. Per-wallet Android version coverage and reproducible receipts for that coverage remain unverified here. MCP tools expose previews and actions for payments, swaps and selected DeFi venues, with execution dependent on the wallet backend, supported route and approval. [Android release](https://github.com/mstevens843/solana-agent-wallet-adapter/releases/tag/v1.0.5) · [Tool inventory and status](https://github.com/mstevens843/solana-agent-wallet-adapter/blob/f00f17f8283c1fca259cefc5d402ef07b463b899/packages/mcp-server/README.md)

**Two recurrence models.** Scheduled payments in the MCP bridge create an approval inbox item each time a payment is due. Separately, source implements streaming payments using one wallet-approved SPL delegate allowance, off-chain vouchers, and delegate-signed settlement. Expiry in this design is enforced off-chain by the settlement service. The on-chain controls are the allowance and owner revocation. The project's security review identifies a mainnet release gate for the reviewed settlement path. Published source does not establish that this mode is generally deployed. [Recurring MCP payments](https://github.com/mstevens843/solana-agent-wallet-adapter/blob/f00f17f8283c1fca259cefc5d402ef07b463b899/packages/mcp-server/README.md#real-wallet-bridge-mode) · [Streaming implementation](https://github.com/mstevens843/solana-agent-wallet-adapter/blob/f00f17f8283c1fca259cefc5d402ef07b463b899/packages/streaming-sessions/README.md) · [Streaming review and gate](https://github.com/mstevens843/solana-agent-wallet-adapter/blob/f00f17f8283c1fca259cefc5d402ef07b463b899/docs/streaming-settlement-security-review.md#pre-mainnet-release-gate)

**Implication for AGUS.** Borrow the separation between a prepared action, a wallet-controlled approval and a receipt. Agentic is a close precedent for existing-wallet routing. It also illustrates the security difference between scheduled prompts and delegated settlement.

## HeyElsa

**Vendor-documented product.** The field guide says signup creates an EVM-compatible wallet and a Solana wallet under the Elsa Smart Wallet offering. Users can also connect their own externally owned wallet. The public product documents conversational swaps, bridges, sends, portfolio queries, staking, yield optimization and limit orders. Its public FAQ describes a review card and a confirmation step before signing, and says the user or chosen wallet provider signs. It advertises a separate Terminal workflow where signing stays with the local wallet. [Field guide](https://docs.heyelsa.ai/a-field-guide-to-heyelsa) · [Product and FAQ](https://www.heyelsa.ai/)

**Vendor-described architecture.** The issuer's MiCA whitepaper describes Copilot, Widget/SDK and AgentOS, with intent, orchestration, validation, execution and observability layers. Its wallet protocol discussion is in the section about Base and the ELSA token and names WalletConnect and injected wallets. The public sources reviewed do not specify the Solana embedded wallet's owner, signing provider, account model, session policy or on-chain program. They also leave open which limit order or yield features are available to an external Solana wallet, what grants authorize them, and whether multiple independent Solana wallets can stay linked and sign in one Android session. The public app returned HTTP 403 in this environment, so workflow coverage here is based on first-party publications. [Whitepaper](https://docs.heyelsa.ai/elsa-white-paper/heyelsa-mica-whitepaper) · [Public app](https://app.heyelsa.ai/)

**Implication for AGUS.** HeyElsa provides a reference for conversational intent, review cards and combining wallet choices in one experience. The label “Smart Wallet” provides no basis for attributing a Solana implementation to Privy, Swig or any other provider. Background automation advertised for the product is insufficient evidence of standing authority over a connected Phantom, Solflare or Backpack account.

## Other implemented infrastructure

- **Solana Foundation Subscriptions** publishes a Rust program, TypeScript and Rust clients, a local demo, integration tests and audited release artifacts. It implements token pulls under standing grants while the source remains the existing wallet's ATA. Local implementation and published releases establish a technical reference. Deployment identity, upgrade authority and program bytes for an eventual target network remain a separate verification step. [Pinned program and demo](https://github.com/solana-foundation/subscriptions/tree/efb735d01ac46e8240864c9e3fc603d2341714da) · [Audited program release](https://github.com/solana-foundation/subscriptions/releases/tag/program-v0.5.0)
- **Swig** publishes a Solana smart-wallet program and SDKs for role-based execution. The official documentation gives a swap path where the Swig account owns the assets. **Privy** documents external-wallet connection and separately provisioned additional signers on Privy wallets. **Phantom MCP** documents direct agent operations through Phantom embedded wallets. These are distinct alternatives for optional new-account flows. [Swig protocol](https://github.com/anagrambuild/swig-wallet/tree/c64127837995818ef5d1e161bbc367391a1b5765) · [Swig swaps](https://build.onswig.com/solana/use-cases/swaps.md) · [Privy wallet signers](https://docs.privy.io/wallets/using-wallets/signers/overview.md) · [Phantom MCP setup](https://docs.phantom.com/phantom-mcp-server/setup)

- **Jupiter Trigger V2** provides a concrete Solana example of automated limit orders and dollar-cost averaging. The user signs a challenge and a deposit, and the deposit moves the funds used by orders to a per-wallet vault that Jupiter identifies as Privy-managed and custodial. Fills can then run automatically. Cancelling a DCA order returns the unfilled balance through a signed withdrawal flow. This demonstrates funded order automation independently of HeyElsa's undocumented signing architecture. [Trigger V2](https://developers.jup.ag/docs/trigger/index.md) · [Vault and deposit](https://developers.jup.ag/docs/trigger/deposit.md) · [DCA cancellation](https://developers.jup.ag/docs/trigger/dca-cancel.md)
