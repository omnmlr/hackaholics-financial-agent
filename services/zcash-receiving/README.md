# AGUS native Testnet receiving wallet

Isolated Railway service `agus-zcash-receiving`; durable `/data` volume. Counterpart uses the private service domain and a backend-only bearer credential. No owner/signing endpoint is forwarded. Native `zaw daemon` listens only on loopback and stays **locked**. Creation is first-run-only; encrypted seed and viewing database remain on the wallet volume, never in an image, browser, model prompt, API response, Git or evidence.

Native source: Sofiia7/zec-agent-wallet commit `0a726bccbfe4a79348f77780c9fcb61789be9cb2` (zaw 0.1.2), MIT. Exact locked `librustzcash` dependencies: backend 0.25.0 / sqlite 0.23.0 / protocol 0.11.0. These support current NU7 Testnet. Docker builds this source with one bounded seed-at-rest scrypt parameter (`log_n=18`, 256 MiB) because upstream auto-calibration caused native initialization to receive SIGKILL under Railway's 1 GiB ceiling. The secret is generated with 384 bits of entropy. Scanner, wallet generation, cryptography and proof code are unchanged. Source license is retained.

Each invoice is permanently bound to an idempotency identity, terms digest, exact zatoshis and a fresh Orchard-only Unified address generated by the native wallet. The bridge reads only decrypted output metadata from the native database; it does not select memos or private keys. NU7 uses the Ironwood pool (code 4) with the Orchard Unified receiver; evidence distinguishes pool 3 and 4 rather than mislabelling them.

The application requires one exact-value, non-change received output at that dedicated address, a wallet-derived mined block and at least 3 consistent confirmations. Partial, excess, split, stale, reorged, late, different-wallet or mismatched terms observations cannot settle the invoice. Transaction reuse is rejected by the existing database-wide settlement guard. Distinct invoices paid in one transaction currently require manual review rather than silently reusing settlement evidence.

Invoice settlement, request confirmation, reminder completion and audit are committed together through the existing backend. Cancelled reminders are not reactivated. Receiving creation does not approve an external action or activate its proposed reminder. A runtime-only Next.js watcher checks persisted requests every 20 seconds; the UI refreshes every 30 seconds. Retries and restarts do not allocate another address for the same invoice.

The public receiving-only HTTPS domain is authenticated and exists for acceptance testing; service-to-service traffic uses private networking. `/healthz` discloses only liveness. Bearer-protected routes are `/status`, `POST /invoices`, `GET /invoices/<binding>`. Every other route, including signing/owner routes, is unavailable. HTTP requests are not logged. Never add a generic native RPC proxy.

Light clients trust lightwalletd for chain availability and metadata. Wallet trial decryption establishes receipt; public metadata alone cannot prove private settlement. Automatic settlement stops if the scanned tip is stale or the wallet is behind.
